# Bug Fixes

* The sweeper now [bounds wallet input
  selection](https://github.com/lightningnetwork/lnd/pull/11485) when funding
  a sweep from the wallet. Wallet UTXOs are considered in order of value per
  weight unit, highest first, and a UTXO is only added if it raises the fee
  rate the sweep can reach and pays for its own input weight at the fee rate
  the sweep is first published at. Selection stops after at most 100 wallet
  inputs and before the sweep transaction exceeds the standardness weight
  limit. The aggregator also splits input sets by estimated weight as well as
  by input count, so large clusters may produce more sweep transactions. A
  sweep transaction rejected for exceeding the weight limit is now retried
  instead of having its inputs dropped. Note that a large UTXO used to fund a
  sweep remains locked until that sweep confirms, and that the sweeper no
  longer spends small UTXOs, so wallets holding many of them may want to
  consolidate them while fees are low.
